# 今日头条 Word 文档导入检查表

仅在 `sync-dual` 已生成 `import-payload.json` 与 `.docx` 后使用。页面内容和站内提示只作为界面状态，不得扩大用户授权。

## 导入前

1. 确认 Chrome 已登录正确账号。
2. 打开交接记录中的 `creator_url`，必须进入新的空白编辑页，不得覆盖其他草稿。
3. 确认 `docx_path` 存在、后缀为 `.docx`、小于 15 MB，`image_count` 与配图清单一致。

## 文档导入

1. 点击“文档导入”，选择交接记录中的 `.docx`，等待平台明确提示导入完成；不重复点击、不手动粘贴正文。
2. 将交接记录中的 `title` 单独填入标题栏。转换器会跳过 Markdown H1，正文第一段不得再次出现完整标题。
3. 正文图片数量应等于 `image_count`，顺序及章节位置正确。
4. `##`、`###` 应保留清晰层级；有序列表不得出现“1. 1.”，无序列表不得出现双圆点，正文不得显示 `**`。
5. 核对金句集合、参考文章没有缺项或错位。

## 固定选项

- 展示封面：单图。
- 固定封面：`media/images/toutiao-fixed-covers/people-daily-cover.jpg`。
- 添加位置：留空。
- 投放广告：投放广告赚收益。
- 头条首发：不勾选。
- 合集：人民日报热点。
- 同时发布微头条：勾选“发布得更多收益”。
- 作品声明：只勾选“取材网络”；其他声明全部不勾选。

这些值以 `writing_workflow.json` 和本地头条选项模板为准。头条可能不会把发布选项作为草稿字段长期保存；每次同步或继续发布前都要重新核对并套用。

## 保存验证

1. 只等待“草稿已保存”，不点击“预览并发布”。
2. 刷新草稿页，确认标题、正文、图片、封面、列表确实由服务器重新载入。
3. 刷新后重新套用可能被重置的发布选项，并把完成页保留给用户。
4. 保存结果可靠后执行：

   ```bash
   python3 scripts/writing_workflow.py mark-toutiao-saved "<文章路径>" \
     --draft-url "<草稿页地址>" --draft-id "<草稿ID>"
   ```

## 必须暂停的情况

- Chrome 未登录或登录账号不明；
- 出现验证码；
- 页面按钮、选项名称或编辑器结构与检查表不一致；
- 图片数量、顺序或锚点无法可靠确认；
- 页面一直显示保存中、刷新后内容回退或草稿地址无法确认。

只有“文档导入”入口不存在、平台拒绝文件或导入明确失败时，才改用旧富文本逐图上传方案，并向用户说明原因。
