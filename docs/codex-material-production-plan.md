# Codex 人民日报教研标注与公众号写作固定方案

这份方案用于指导 Codex 或其他 AI 处理人民日报文章素材。目标不是简单摘金句，而是把文章变成申论教学、结构化面试教学和公众号持续输出都能使用的资料资产。

以后处理新文章时，请优先按本方案执行。

如果用户要求从一段时间的人民日报中完成“梳理 - 选题 - 写公众号文章 - 生成配图 - 生成 PPT - 生成小红书图片”，请同时执行：

```text
docs/cross-platform-content-package-workflow.md
```

其中，小红书图片默认使用 `3:4` 竖版规格，不再使用 `4:3` 横版规格。

## 一、最终产出是什么

每次处理素材时，先完成单篇文章内的 `Codex 教研速读` 标注。每次完成文章写作，固定形成四个相互关联的文件：

1. 公众号成稿：让读者带走框架、素材和答题方法。
2. 小红书卡片脚本：完整转译公众号文章逻辑，便于后续直接生成卡片。
3. 选题教研复盘：把多篇文章串成申论、面试、公众号可用的主线。
4. 公众号过程稿：保留来源分工、逻辑搭建、正文工作稿和取舍说明。

小红书卡片脚本集中放在：

```text
data/xiaohongshu/NN-xiaohongshu-<topic-slug>-card-script.md
```

公众号文章成稿按来源分为两个系列：

```text
data/articles/人民日报系列/   # 人民日报选题，沿用数字编号
data/articles/热点系列/       # 热点分析，使用“热点+数字”编号
```

文件名优先使用中文标题，例如：

```text
31-人民日报讲某主题：中文标题.md
热点2-官媒视角看某热点：中文标题.md
```

日期目录里的 `wechat-<topic-slug>.md` 可以继续作为过程稿或出品包引用文件；老师日常查找、复用、二次编辑时，以两个系列目录里的中文标题稿为准。文章发表后由老师手动移入 `data/articles/往期文章/` 下对应系列，并在 `data/articles/文章索引.md` 更新链接。

如果用户要求做跨平台出品包，则在固定四项基础上继续形成：

5. 主题 shortlist：从素材支撑度、考试迁移度、读者痛点、视觉表达度中筛选主题。
6. 带配图版公众号文章：公众号配图默认 `16:9`，建议 `1920×1080`。
7. 小红书图片：默认 `3:4` 竖版，建议 `1080×1440` 或 `1440×1920`。
8. 课堂 PPT：默认 `16:9`，配套讲稿或讲解提示。

## 二、单篇文章标注规则

### 1. 标注位置

默认写在文章前端，放在 YAML frontmatter 和原有自动批注之后、正文标题之前。这样其他 AI 下次只读文件前几十行，就能先获取关键信息。

如果文章前端结构复杂，或已经有多个 AI 的标注区，则写在文末，标题使用：

```markdown
## Codex 教研标注
```

无论写在前端还是文末，都不要删除原文、自动批注或其他 AI 已经写入的内容。

### 2. 标注必须注明来源

每个 Codex 标注都要明确写出：

- 由 Codex 完成
- 标注日期
- 是否已经读完原文
- 适合申论、面试、公众号中的哪些用途

### 3. 推荐 callout 模板

优先使用下面这个模板，保持所有文章格式一致。

```markdown
> [!codex] Codex 教研速读｜YYYY-MM-DD
> **完成者**：Codex
> **阅读状态**：已读原文，以下为教研转译，不替代原文事实。
> **一句话判断**：这篇文章最值得提取的核心判断。
> **核心事实**：用 2-4 条写清楚人物、事件、数据、政策、做法。
> **治理逻辑**：问题是什么，做法是什么，结果是什么，机制是什么。
> **申论可用**：适合哪些主题；可转成什么分论点或对策表达。
> **面试可用**：适合什么题型；可以怎么答。
> **公众号可用**：可以写成什么选题；读者能获得什么。
> **关键词**：基层治理 / 民生保障 / 反形式主义 / 新质生产力 / 绿色转型等。
> **复用提醒**：哪些地方不能误用、夸大或脱离语境。
```

### 4. 可选的细分 callout

如果文章特别重要，可以在主速读下面再追加 2 到 4 个细分 callout。

```markdown
> [!abstract] Codex 框架
> 问题发现 - 责任承接 - 协同办理 - 进度反馈 - 复盘长效。

> [!example] Codex 案例
> 具体案例概括。保留地点、主体、时间和关键数据。

> [!tip] Codex 考场转译
> 申论怎么写，面试怎么答，不要只停留在摘句。

> [!info] Codex 公众号选题
> 题目方向、读者痛点、可展开的文章结构。
```

### 5. 写 callout 时的注意事项

- 不要大段复制原文，只提炼关键信息。
- 不要把自己的判断写成原文事实。
- 不要只写主题标签，要写清楚“为什么有用”。
- 不要用标题当唯一标识；至少保留日期、版面、标题、source_url。
- 如果是广告版、地方形象稿、宣传性内容，要在复用提醒里标明“谨慎使用”。
- 如果文章只适合作为辅助素材，也要标明等级，不要强行深挖。

## 三、单篇文章处理流程

每读完一篇文章，按下面顺序处理：

### 第一步：先判定价值等级

| 等级 | 判断标准 | 处理方式 |
|---|---|---|
| A | 有完整的“问题-做法-成效-机制”，能进课、出题、写公众号 | 写完整 Codex callout |
| B | 有好案例、好数据、好表达，但逻辑不完整 | 写简版 Codex callout |
| C | 信息单一、教学迁移弱、宣传属性强 | 只写一句话索引，或不写入正文 |

### 第二步：提取四层信息

1. 事实层：谁、何时、何地、发生什么、有什么数据。
2. 治理层：问题如何被发现，责任如何承接，部门如何协同，结果如何反馈。
3. 教学层：申论可以写什么，面试可以答什么，能否形成分论点。
4. 内容层：公众号可以用什么标题，读者读完获得什么方法。

### 第三步：写入 Codex callout

不要等到一天结束再补。读完一篇、判断有价值，就及时写入该文章的 Codex callout。

### 第四步：留下“复用提醒”

每篇文章都要写一句“复用提醒”。这是防止材料被误用的安全阀。

常见提醒：

- 这是个案，不要夸大成普遍完成。
- 这是理论文章，需要搭配具体案例使用。
- 这是广告版材料，可取数据和结构，不宜当作中立报道。
- 数据有明确时间范围，引用时必须带上日期。

## 四、每日复盘流程

当天处理多篇文章后，生成一份每日复盘，放在：

```text
data/analysis/YYYY-MM-DD/YYYY-MM-DD-teaching-content-review.md
```

每日复盘固定包含：

1. 一句话总判断：当天文章共同指向什么核心命题。
2. 高价值文章清单：列出 A 类和 B+ 类文章。
3. 教学主线：通常 3 到 5 条，不要贪多。
4. 申论框架：每条主线给出可写分论点和对策。
5. 面试题库：至少 5 道题，每道题给答题要点。
6. 公众号专题库：至少 3 个专题，每个专题有标题、支撑文章和平台用法。
7. 全日文章取舍清单：每篇文章给等级和处理建议。

每日复盘不是统计报表，而是教研资产。写的时候要回答一个问题：

这一天的文章，能帮考生多会哪一种答题能力？

## 五、公众号文章写作框架

公众号文章不是资料罗列，而是一次“带着考生学会一种能力”的阅读体验。

### 1. 选题标准

优先选择能同时满足三点的主题：

- 考生常犯错：例如只会背金句、只会写空话、面试只会安抚情绪。
- 人民日报有案例支撑：最好有 2 到 4 篇文章互相支撑。
- 读完能带走方法：能形成框架、句式、答题步骤或训练题。

成稿前先判断文章类型：

- **人民日报系列**：由人民日报文章或一组人民日报材料直接形成主题分析，使用连续数字编号。
- **热点系列**：由近期热点和多家官媒集中评论形成分析入口，再用人民日报材料补充治理逻辑和考试迁移，使用“热点1、热点2……”独立编号。

热点系列的开头重点回答“官媒为什么这样分析、不同媒体分别抓住了什么”，不要预设“很多同学第一反应是什么”，也不要只就热点复述热点。

### 2. 标题公式

标题要有一点冲突感或提醒感，避免平铺直叙。

如果文章核心素材来自人民日报，标题中优先显性出现“人民日报”四个字，让读者一眼知道这不是泛泛时评，而是在学习人民日报材料和答题方法。标题不要只写主题词，要同时给出冲突、对象和收益。

可用公式：

- 别只做 A，真正该学的是 B
- 很多考生忽略了，人民日报这篇文章真正值钱的是 X
- 写 X 题，别再只说 Y
- 一篇人民日报，讲透一个申论高频能力
- 结构化面试想答出区分度，先学会 X
- 别再空喊 A：人民日报这篇文章，讲透 B 的高分写法
- 人民日报这篇/这组文章，真正该学的不是 A，而是 B
- 学人民日报写 X：别再只说 A，要写出 B

示例：

```text
别只背金句了：人民日报这一天，真正该学的是“落地见效”
别再空喊“以人为本”：人民日报这条上学路，讲透城市治理高分写法
```

### 3. 开头写法

开头不要先讲背景，要先打中考生痛点。

推荐结构：

1. 先写考生常见动作。
2. 再指出这个动作为什么不够。
3. 再引出今天要解决的能力。

示例节奏：

```text
很多同学读人民日报，最容易陷入一个误区：

看到一句好话，摘下来。
看到一个案例，记下来。
看到一个政策名，背下来。

然后呢？

到了申论考场，还是只会写……
```

### 4. 中段写法

中段按“案例 - 逻辑 - 考场转译”推进。

每一节都要包含：

- 一个具体案例或文章事实
- 一个核心概念
- 一段申论可用表达
- 一道面试题或答题要点

不要连续堆材料。每讲一个材料，就要马上告诉考生：

- 这个材料能说明什么？
- 申论怎么用？
- 面试怎么答？
- 不能怎么误用？

### 5. 文章节奏

公众号要有阅读节奏，可以使用：

- 短句提问：然后呢？问题在哪里？
- 对比句：不是 A，而是 B。
- 递进句：不只是态度，更是流程；不只是记录，更是结果。
- 固定框架：发现问题、接住问题、协同解决、反馈进度、复盘长效。
- 小结句：这就叫治理闭环。

不要写成长段公文。每段尽量只表达一个意思。

也不要把每一句都单独拆成一行。公众号草稿要适合 Markdown 渲染后的网页阅读：

- 连续解释、连续叙述的短句，合并成 2 到 4 句的自然段。
- 转折句、提问句、结论句可以单独成段，用来制造停顿。
- 一组并列动作、步骤、答题要点，优先用编号列表或项目符号。
- 核心判断、答题公式、可复用表达，用 `**加粗**` 突出。
- 申论可用句、面试题、总公式、关键追问，用 `>` 引用块突出。
- 不要为了追求口播感，把整篇写成“一行一句”；也不要写成大段公文墙。

### 6. Markdown 强调规则

写公众号文章时，默认用 Markdown 做轻量排版：

- 标题和小标题用 `#`、`##`、`###`，让读者能快速扫读结构。
- 关键概念第一次出现时可以加粗，例如 `**城市体检**`、`**服务前移**`、`**治理闭环**`。
- 重要结论用引用块单独展示，例如：

```markdown
> **好的城市治理，不是把城市变得更好看，而是把公共服务嵌进人的日常生活。**
```

- 面试题题干用引用块，答题步骤用加粗编号段落。
- 申论可用表达用引用块，方便后续复制到讲义或训练材料。
- 一篇文章中加粗和引用要服务重点，不要整段整段加粗。

### 7. 金句集合

公众号成稿正文结束后，必须先追加：

````markdown
## 金句集合

```text
1. 金句 1

2. 金句 2
```
````

金句集合用于用户直接复制到小红书文本框。整理规则：

- 只收录正文中已经出现，或从正文核心判断高度凝练出的表达。
- 优先收录“不是 A，而是 B”“要从 A 到 B”“可直接写进申论/面试”的句子。
- 放在一个编号 `text` 代码块里，便于一次性复制。
- 不要把参考文章、脚注、长段事实堆进去。
- 数量不必固定，通常 8 到 15 条；宁可少而精，不要把全文重新摘一遍。

### 7b. 参考文章标注

金句集合之后，再追加参考文章栏目，标题统一写：

```markdown
## 参考文章
```

参考文章至少包含：

- 作者，没有作者时可省略。
- 文章标题。
- 《人民日报》日期和版面。

推荐格式：

```markdown
1. 作者：《文章标题》，YYYY 年 M 月 D 日，第 XX 版（版面名称）。
```

如果一篇公众号文章用了多篇人民日报素材，按正文引用的重要程度或文章日期/版面顺序列出。参考文章只标注实际用于正文观点、案例、数据或题目设计的文章，不要把当天所有文章都塞进去。

### 8. 结尾写法

结尾不要只喊口号，要帮读者完成一次认知升级。

推荐收束：

```text
人民日报不是背诵本，而是训练治理思维的样本。

真正会学的人，会从一篇文章里看三件事：

它发现了什么问题？
它用了什么办法解决？
它最后形成了什么机制？
```

## 六、公众号文章固定结构模板

```markdown
# 标题

开头：指出考生常见误区，引出今天要学的能力。
排版：不要整篇一行一句；连续解释合并成自然段，关键判断用加粗或引用块突出。

## 一、用一个小案例抓住核心问题

写具体事实，不要先讲大道理。
提炼核心概念。
给出一句申论可用表达。

## 二、把概念拆成答题框架

把核心概念拆成 4 到 6 个动作。
每个动作都要能写进申论或说进面试。

## 三、把材料转成一道面试题

给出题目。
先展示普通答法为什么没有亮点。
再给出有区分度的答题思路。

## 四、补一个关系辨析或反面提醒

例如：减负不是少干事，而是少干无效的事。
例如：创新不是造亮点，而是解决真问题。

## 五、给读者一套可带走的框架

用一句总公式收束。
列出可以直接迁移的 4 到 6 个动作。

## 六、结尾拔高

告诉读者以后应该如何读人民日报。
让文章落在能力提升上，而不是材料堆积上。

## 金句集合

用一个 `text` 代码块集中列出正文中最适合复制到小红书的金句。

## 参考文章

列出本篇实际使用的人民日报文章：作者、标题、日期、版面，不附原文链接。
```

## 七、交给其他 AI 的标准提示词

如果要让其他 AI 按本方案处理文章，可以直接复制下面这段：

```text
你正在处理人民日报素材库，读者是一名公务员培训师，服务对象是申论考生和结构化面试考生。

请不要只摘金句。请把文章转成三类资产：申论教学资产、结构化面试教学资产、公众号运营资产。

处理每篇文章时，请先判断 A/B/C 等级，再提取事实层、治理层、教学层、内容层信息。

请在原文中追加或插入 Codex 风格 callout，标明“由 Codex/当前 AI 完成”，并包含：一句话判断、核心事实、治理逻辑、申论可用、面试可用、公众号可用、关键词、复用提醒。

如果写公众号文章，请按“考生误区 - 具体案例 - 治理逻辑 - 申论转译 - 面试题示范 - 可带走框架 - 结尾拔高”的结构写，要求读者读完有明确获得感。

不要删除原文、旧批注或其他 AI 的内容。不要用标题当唯一标识。不要把自己的判断写成原文事实。
```

## 八、以后 Codex 的默认执行口径

以后 Codex 在本项目中处理人民日报文章时，默认执行以下动作：

1. 先读取文章前端已有的 Codex callout。
2. 如果 callout 信息足够，只用它做初步整合；必要时再回读原文核实。
3. 如果没有 Codex callout，读完整篇原文后，先写入 Codex callout。
4. 每篇 A 类文章必须写完整 callout。
5. 每天或每个专题处理结束后，生成每日复盘或专题复盘。
6. 写公众号文章时，必须同时服务申论和结构化面试，不写泛泛的时评。

如果用户指定的是一个日期段，并且目标是后续出文章、配图、PPT、小红书，则按下面顺序执行：

1. 先梳理日期段文章，生成结构化素材资产。
2. 再生成主题 shortlist，不直接跳到写文章。
3. 用户确定主题后，再写公众号文章。
4. 文章定稿后，先写视觉设计 brief。
5. 公众号配图用 `16:9`，小红书图片用 `3:4` 竖版。
6. 中文标题、正文、引用、表格优先由 Markdown、HTML 或 PPTX 排版，不交给图像模型直接生成。
7. imagegen 只用于无文字背景、插画、纹理、抽象视觉或参考风格变体。
8. 小红书卡片脚本归档到 `data/xiaohongshu/`；公众号过程稿、选题教研复盘、视觉 brief、讲稿提示归档到 `data/analysis/<period>/` 或其 `deliverables/<topic-slug>/`。
9. 配图、PPTX、视频、音频等非文本成品归档到 `media/`，并在 `media/_index.md` 补一行索引，记录本地位置和网盘位置。

这样做的目的，是让素材库从“文章堆”变成“可复用的教研资产库”，同时降低后续 AI 重复阅读原文造成的 token 消耗。
