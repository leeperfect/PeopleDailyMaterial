# Mac 与云端 Claude 协作

## 分工与资料边界

GitHub 是经审查文本和程序的共同中转站。Mac 保管完整资料与运行进度，负责采集、人工选题、数据库、得到送稿、Notion/妙搭同步和平台草稿。云端 Claude 阅读资料、形成可审查的文字产物或修改任务指定的程序，完成后提交到自己的任务分支。

本次接入基线为 `3.7-拓展今日头条文章自动同步功能`，不是默认分支 `main`。每次开工都要从最新交接卡获取精确提交，不长期沿用本次基线。

仓库中的 `data/raw/`、`data/vault/` 和政策原文可用于阅读与来源核对。人工选题以 Mac 的 `data/core/material_assets.sqlite` 为准，包含 `content_ideas` 和 `content_idea_notes`；写作进度以 Mac 的 `data/core/writing_workflow_state.json` 为准。Git 忽略这些资料，重新下载仓库不能恢复它们。

历史上已经跟踪过的其他 SQLite 文件也不能当作 Mac 当前进度。`.gitignore` 不会自动移除历史已跟踪文件。本次不删除这些有效资料，也不改写仓库历史。

## 每次任务的交接卡

由 Mac 填好以下内容，再把任务交给云端。没有明确文件范围时先阅读，不修改。

```text
任务：
来源分支：
基准提交（完整 SHA）：
云端任务分支：claude/日期-任务名称
文章编号 / Article ID / 选题 ID：
本次允许修改的文件：
本次只读参考资料：
Mac 暂停编辑的文章与文件：
资料摘录的生成时间与范围：
交付内容及检查要求：
```

同一篇文章只能由一端编辑。云端形成新稿时先使用任务目录，例如 `data/analysis/cloud-tasks/<任务名>/`；正式编号、文章索引、选题状态和本地写作流程由 Mac 审查后登记。已指定文章编号且 Mac 暂停编辑时，可以按任务卡直接修改指定文章。云端交稿不触发送稿或发布。

## 云端建立任务分支

在云端终端执行；以下占位符必须替换为任务卡内容。全新目录才运行 clone，已有目录先检查未提交内容，禁止用重置或清理命令覆盖现场。

```bash
git clone --single-branch --branch '3.7-拓展今日头条文章自动同步功能' https://github.com/leeperfect/PeopleDailyMaterial.git
cd PeopleDailyMaterial
git rev-parse HEAD
git switch -c 'claude/日期-任务名称' '<完整基准提交>'
```

先核对基准提交可见，再读 `AGENTS.md`、`CLAUDE.md`、`COMMIT_GUIDE.md` 和 `PROJECT_PROFILE.md`。不要把 Mac 私密配置复制到云端。云端缺少数据库时，使用公开原文与经审查任务摘录；不得为了恢复状态而运行全库重建、选题精筛或外部同步。

完成后检查 `git diff`，仅按文件路径添加任务产物，使用项目规定的中文提交描述，普通推送自己的分支。GitHub 登录与 Claude 登录分别验证；能下载公开仓库不代表有推送权限，本机 Claude 登录成功也不代表云端已登录。

## 不完整状态的交接

默认只交接本次任务所需的选题、状态和来源摘录，注明生成时间、文章编号、Article ID 与基准提交。私密备注和外部平台标识留在 Mac，不把完整写作状态映射提交到公开仓库。

确需数据库时，Mac 先通过 SQLite 的 backup 接口生成一致快照，检查内容后通过双方确认的私密渠道交付；不要直接复制正在写入的数据库及 WAL 文件。接收端将快照放入已忽略的 `.local/cloud-handoff/`，设置只读权限，并使用 `sqlite3.connect('file:路径?mode=ro', uri=True)` 打开。只读权限是防误改措施，数据库内容仍需按私密资料保管。

云端不得回传数据库覆盖主库。需要改变人工选题或写作状态时，提交按稳定 ID 列出的变更建议，由 Mac 核验后写入。图片和媒体通过现有网盘渠道交接，GitHub 只保留媒体索引。

## Mac 审查与合并

Mac 先停止编辑交接文件，检查当前工作区，获取云端分支，再比较云端分支相对交接提交的文件清单和完整差异。检查是否越界改动数据库、运行状态、原始资料、配置、媒体或不相关文章；确认新增内容适合公开，并按改动运行必要检查。

在临时目录或独立工作副本预演合并。有冲突先保留双方版本并解决，不使用整批覆盖、强制推送或清空工作区。审查通过才在 Mac 工作分支合并，随后按原流程登记进度；不得自动合并到 `main`。云端任务完成后保留提交记录，分支删除另行安排。

当前已有 GitHub 到 CNB 的自动镜像，推送 GitHub 可能触发镜像；镜像已关闭强制推送，发生分歧时应人工核查失败原因。既有采集自动任务不属于云端 Claude 的工作范围，不要在云端重复启动。

## 首次协作验收

1. Mac 将经审查资料推送到工作分支，并记录远端完整提交。
2. 使用全新临时副本检出该分支，确认新资料和协作规则齐全；此项只验证 GitHub 分发。
3. 云端确认 Claude 与 GitHub 登录，核对同一提交，建立自己的任务分支。
4. 云端仅新增一份任务回执，记录基准提交及阅读结果，按中文规范提交、推送。
5. Mac 获取该任务分支，核对仅有回执改动，在临时副本预演合并，再决定是否合并。

只有第 3—5 步实际完成，才算云端协作验收通过。Mac 临时副本测试不能替代云端登录与交稿验证。
