# 公众号视觉规范：zen-whitespace 正文 × fresh 线描配图

> 一句话：**正文用 gzh-design 的「留白禅意风」(zen-whitespace)，配图用 baoyu-xhs-images 的 fresh 线描画法，配色统一取自正文主题。画风固定，构图随内容变。**

## 1. 分工

| 环节 | 负责 | 产出 |
|---|---|---|
| 判断哪里需要图、图里解释什么 | 写作/配图判断（每篇 3–5 张，对应文章核心框架） | 配图清单：位置、核心问题、构图类型 |
| 画成什么样 | fresh 线描规范（本文件第 3 节） | `media/images/<日期>-<简称>/fig-NN-xx.png` |
| 整篇排版 | gzh-design `zen-whitespace` 主题 | 纯 `<section>` 正文 HTML |

## 2. 配色（全篇统一）

| 用途 | 色值 |
|---|---|
| 主色 / 小米橙（章节编号、短线、标签、关键箭头与节点；官方品牌橙 Pantone 1505 C） | `#FF6900` |
| 锚点加粗文字 / 深橙（小字号正文里保证可读性） | `#E65100` |
| 关键词下划线 / 浅橙（正文标记、图中辅助分隔与次要提示、浅色填充） | `#FFCAB3` |
| 标题 / 图中文字与主轮廓（近黑） | `#2B2B2B` |
| 正文 | `#525252` |
| 辅助小字 / 图注 | `#A3A3A3` |
| 细线 | `#E8E8E8` |
| 底色 | 正文 `#FFFFFF`；配图白或极浅灰白（约 `#FAFAF8`） |

旧红白色系（`#DC2626` / `#FECACA`）与砖红固定头图不再用于新体系文章；墨绿 `#4A5D52` / 灰绿 `#B5C8BC` 已于 2026-11-16 停用。

## 3. 配图画风（fresh 线描，固定）

- 背景：白或极浅灰白，大量留白，**弱化或不加外框**，让图自然融入正文。
- 线条：深灰近黑细线，略带手绘感，轮廓清楚；图形内部大多留白。
- 点缀：只用小米橙 `#FF6900`（关键箭头/节点/少量线条）和浅橙 `#FFCAB3`（分隔、次要提示、小面积浅填充）；**无大面积色块、无渐变、无阴影**。
- 文字：大标题 + 短节点 + 必要关系说明；每个节点一行说明为宜；中文必须逐字正确、无错字乱码，手机上清晰可读。
- 每张图只解决一个核心问题。

## 4. 构图规则（随内容变）

| 内容关系 | 构图 |
|---|---|
| 两种做法比较、对错写法 | 左右对照（中间细分隔线，错的一侧用灰、对的一侧用小米橙） |
| 政策如何起作用、环节先后 | 因果链 / 流程链（左→右，分组标题 + 小米橙箭头） |
| 多方协同、多种力量 | 关系图（中心对象 + 四周节点，箭头指向中心） |
| 三要素缺一不可 | 三角关系图 |

## 5. 正文排版（zen-whitespace）

- 读 `~/.codex/skills/gzh-design/`：`SKILL.md`、`references/theme-index.md`、`references/theme-zen-whitespace.md`、`references/common-components.md`，HTML 只从组件库取。
- 结构：引言卡（组件 2）→ 前言段落 → 本文脉络（组件 3，精选 3 点）→ 每章「分割线 4 + 章节标题 5（`01 · 英文标签` + 衬线中文 + 小米橙短线）」→ END（14）。
- 正文段落每段 1–3 处浅橙下划线（7d），短语 4–15 字，只标原文已有文字。
- 加粗只保留原文已有的；原文加粗默认普通加粗 `#2B2B2B`，深橙 `#E65100` 加粗只给核心结论锚点，全文 ≤5 处。
- 列表用要点列表（组件 12 竖排版）；图片用组件 10 细线容器 + 说明。
- 不改写任何正文文字；不在正文里留 `{{作者名}}` 等占位（原文无签名时省略签名区）。

## 6. 封面

- 每篇专用：21:9 主封面 + 1:1 分享图，按 dsh-guizang-design / guizang-social-card-skill 的规范做（瑞士国际风：超细大字、严格网格、只用一个高饱和强调色小米橙 `#FF6900`，配色由 `gz-theme.mjs brand "#FF6900" --family swiss` 生成；不用渐变、阴影、圆角），放在本篇图片目录（`cover-v4-<方向>-21x9.png`、`-1x1.png`）。
- 不覆盖 `media/images/wechat-fixed-covers/` 下的旧固定头图。

## 7. 工具链

1. 原文：得到二润稿（`writing_workflow.py pull` 或分享页逐字保存），逐字不改。
2. 用语预检：`python3 scripts/check_public_wording.py "<成稿>"`，「必须改写」为 0 才能同步。
3. 配图：Grok Bot `GenerateImage`（或本机 baoyu 链路），按第 3–4 节提示词生成；人工逐张核对中文与风格，不合格重画。
4. 插图：Markdown 中 `![图名](media/images/<日期>-<简称>/fig-NN-xx.png)`，更新 `media/_index.md`。
5. 排版：生成 `data/exports/wechat_html/<标题>_排版_留白禅意风(zen-whitespace).html`，再用 `wrap_preview.py` 生成带复制按钮的预览页。
   - zen-whitespace 主题自带墨绿色值，生成后整体换色：`#4A5D52`→`#FF6900`（锚点加粗 `<strong>` 用 `#E65100`），`#B5C8BC`→`#FFCAB3`；文件名带 `-orange`，换色后重跑校验并核对正文文字零差异。
6. 草稿：`publish_wechat_draft.py` 已于 2026-11-18 增加主题自动识别——含 `#FF6900/#FFCAB3` 且不含墨绿/灰绿/红白色值的 HTML 按 zen-whitespace 小米橙放行，红白色值 HTML 仅作旧稿兼容；标准 `sync-dual` 链路可直接使用，无需一次性脚本。只 `draft/add`，作者 `LeePerfect`，开评论、不限粉丝，**不群发**。

## 8. 校验标准

- `component_lint.py`：0 ERROR。
- `validate_gzh_html.py`：0 ERROR、0 WARNING。
- HTML 图片数量/顺序与 Markdown 一致；每个原文段落、标题、列表项都在 HTML 中出现。
- 色值检查：含 `#FF6900`、`#FFCAB3`（加粗 `#E65100`），不含墨绿 `#4A5D52` / 灰绿 `#B5C8BC`，不含红白色值。
- 390px 手机宽度长图预览人工过目：图文间距、下划线密度、配图中文。
