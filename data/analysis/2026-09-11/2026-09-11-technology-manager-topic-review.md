# 选题复盘｜《人民日报》深度分析【技术经理人】

## 一、选题卡要点

- 标题：《人民日报》深度分析【技术经理人】：好技术为什么还需要一个懂市场的合伙人
- 切入角度：承接科技成果转化的历史读者，参考"从'0'到'1'，把'1'拉长"系列，专讲谁来组织转化、如何承担全过程服务及获得长效激励。
- 主例：陕西技术经理人（韦伯灵动、1718名队伍）+ 光谷需求说明书（杨珂案例）。
- 明确边界：不重复既有成果转化全链条、中试设备和耐心资本总论。
- 指定结构：技术好不等于产品有人买 → 先把需求说清 → 再把合作做实 → 从撮合走向陪伴 → 激励与能力一起建设。

## 四、主线逻辑链设计

- 读者常见误区：以为成果转化难在"钱"和"设备"（资金、中试），以为转化就是"把技术卖出去"（一次性交易），以为中介就是"牵线的"（撮合拿佣金）。
- 主线（问题递进链）：

> 为什么需要这个人（两头不沾）→ 他先做什么（把需求说清）→ 他怎么做成（把合作做实）→ 他为什么干得久（从撮合到陪伴）→ 凭什么有人干、干得好（激励与能力建设）

- 递进关系说明：第一节立"技术好不等于有人买"的真问题；第二节给出需求侧动作（需求说明书）；第三节给出供给侧动作（评估、匹配、谈判）；第四节从"做成一单"升级到"陪到底"（凌晨两点、5%股权的含义）；第五节回答"这样的人从哪来、凭什么留"（学院、职称、薪酬、股权）。每一节解决上一节引出的新问题。
- 一句话公式：**撮合一次是交易，陪伴全程才是转化。**

## 五、五节结构与素材分配

1. 技术好不等于产品有人买：西工大无人植保车团队会研发不会做产品（不懂注册、不会商业计划书、不知对接投资者）（来源2）；"两头不沾"（来源3）。深化点：转化的堵点不在技术在翻译，缺的是既懂技术又懂市场的人。
2. 先把需求说清：杨珂案例全流程——进企业反复沟通、写技术需求说明书、把痛点变成靶标、凭学科优势判断找湖北大学何桥宁团队（来源5）；眉县蹲点几周泡田间地头、农资门店，凌晨两点定农资店合作模式（来源2）。深化点：需求不是问出来的清单，是蹲出来的判断；把痛点写成靶标。
3. 再把合作做实：崔高锋动作清单——归纳技术亮点、编制商业计划、对接路演、引入第三方完成价值评估与资信调查、全程谈判、设计股权结构与转化路径（来源1）；杨珂从可行性论证到合同谈判全程跟踪（来源5）。深化点：合作做实的标志是价格谈得成、风险说得清、权责写得下。
4. 从撮合走向陪伴："撮合一下拿些佣金"→持有股权同舟共济（来源2）；编辑手记"把'帮忙'做成'合伙'""一锤子买卖→全生命周期陪伴"（来源3）；韦伯灵动后续：15台车、迭代施肥功能（来源2）。深化点：5%股权的本质是把服务质量和企业成长绑定。
5. 激励与能力一起建设：技术经理人学院三导师制、短期速训+中长期进阶+学历教育（来源2）；"基础底薪+转化奖励+股权增值"多元薪酬（来源2）；55个持股案例、事务所、职称资格（来源2）；江苏20条"壮大职业化技术经理人队伍"单列（来源4）；2027年5000名目标（来源2）。深化点：职业可持续=能力有处学+收入有奔头+身份有认可。

## 六、教学转译设计（申论题卡 + 第六节）

- 总公式：技术经理人机制 = 组织者定位（谁来干）→ 需求翻译（把痛点写成靶标）→ 交易落地（评估谈判股权设计）→ 全程陪伴（从撮合到合伙）→ 制度支撑（培养+激励+职称）。
- 申论三动作：
  1. 用"两头不沾"立问题："科研人员不熟市场，经营主体不懂技术，成果转化的堵点往往不在技术本身，而在两种语言之间缺少翻译。"
  2. 用"需求说明书"写对策："推动转化服务从供给导向转向需求导向，组织专业力量深入企业现场，把模糊的痛点梳理成可验证、可对接的需求说明。"
  3. 用"股权绑定"写激励："探索服务作价入股等模式，让转化服务者的收益与企业成长挂钩，把一次性撮合变成长周期合伙。"
- 申论题卡结构（参照 89 号题卡）：母题定位 → 常见低分写法（只写建平台、只写给政策、只写撮合中介、只写人才引进）→ 问题分析框架 → 对策框架 → 总论点 → 材料概括题模板 → 面试题框架 → 使用边界。
- 面试题：市科技局拟建技术经理人队伍，成果多但转化少，让你牵头组建队伍并设计工作机制，怎么办。
- 高分表达储备：两头不沾 / 把痛点写成靶标 / 需求说明书 / 撮合拿佣金、持股当合伙人 / 全生命周期陪伴 / 一锤子买卖。

## 七、与既有选题的区分核验

- 与 23《科技成果转化》区分：23 号讲链条全环节（场景、服务链、人才承接），是"链"的视角；本篇讲"人"的视角——组织者、翻译者、陪伴者的具体角色，不重复链条总论。
- 与 49《科技金融》区分：49 号讲资本陪创新走完周期（耐心资本）；本篇讲"人"陪技术走完转化（技术经理人），钱的逻辑不展开。
- 与 67《中试平台》区分：67 号讲设备与验证环节；本篇完全不涉及中试设备。
- 与 64《新职业》区分：64 号讲新职业制度框架（标准、培训、评价、保障）的通用逻辑；本篇聚焦技术经理人一个职业的具体动作与价值机制，第五节的职称、培训仅作激励支撑，不重复 64 号框架。
