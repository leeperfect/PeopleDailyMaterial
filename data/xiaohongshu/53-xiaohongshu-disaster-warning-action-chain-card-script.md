# 小红书卡片脚本｜防灾救灾：预警如何变成行动

## 视觉总原则

- **规格**：3:4竖版，建议1080×1440，共11张。
- **画面要求**：所有视觉由AI直接生成，不出现人物、人脸、手部、人物剪影或拟人角色。
- **内容策略**：不强行拆成18张；11张足以完整呈现风险、预警、叫应、转移、前置、协同和复盘。
- **视觉母题**：一条红色预警信号穿过风险地图、县乡村通信节点、转移路线、安置点和应急仓库，最终形成闭环。
- **色彩**：深灰暴雨云、预警橙红、应急蓝、安置暖黄、安全绿色；避免整套页面只有红黑两色。
- **排版方式**：AI生成无文字底图，中文标题和正文由HTML/PPTX后置排版，确保文字清晰、无乱码、不溢出。
- **信息密度**：每页解决一个问题，案例数字只保留最能解释机制的部分。

## 01 封面｜预警发了，工作就完成了吗

- **页面目的**：建立认知冲突。
- **主标题**：预警不能只“发出去”
- **副标题**：关键要有人接、马上动
- **重点句**：**预警争取的是时间，行动才能把时间变成安全。**
- **视觉方向**：手机预警信号从云层落下，连接风险地图、村庄节点和安置点，无人物。

## 02 误区页｜“加强预警”为什么还是空

- **页面目的**：解释预警与行动之间的断点。
- **标题**：信息到了手机，不等于群众已经安全
- **正文**：可能有人没看懂、有人不愿走、有人行动不便、有人不知道由谁组织；车辆、路线和安置点也可能尚未启动。
- **重点句**：**预警不是通知完成，而是任务开始。**
- **视觉方向**：预警消息停在多个断裂节点前，分别标示理解、责任、转移和安置障碍。

## 03 总公式｜一条完整防灾行动链

- **页面目的**：给出文章全貌。
- **标题**：从风险排查到复盘改进
- **正文**：风险排查 → 影响预警 → 叫应确认 → 转移安置 → 力量前置 → 协同处置 → 复盘改进
- **重点句**：**七个环节层层相接，任何一处断点都可能让预警失效。**
- **视觉方向**：七段式应急轨道，末端回到风险地图形成闭环。

## 04 风险页｜预警之前先准备四张清单

- **页面目的**：说明精准预警建立在风险底数上。
- **标题**：哪里危险、谁要先转、怎么转、谁负责
- **正文**：风险点清单、重点人员清单、转移资源清单、责任人员清单要动态更新。
- **重点句**：**风险排查不是多填一张表，而是预警一响就知道先找谁。**
- **视觉方向**：数字风险地图旁排列隐患点、重点家庭、路线、责任节点四类图层，无人物。

## 05 转译页｜预警要告诉人们“现在做什么”

- **页面目的**：从天气预报推进到影响预警。
- **标题**：不只报雨量，还要报危险和动作
- **正文**：同样雨量，短时集中降下风险更高。预警要说明危险地点、受影响对象、行动时限和避险要求。
- **场景动作**：家中进水先断电；积水道路要绕行；山区异常立即向高处转移；地下空间进水马上离开。
- **重点句**：**看得懂、能执行、可核验，预警才真正有效。**
- **视觉方向**：暴雨云下分出住宅、道路、山区、工地和地下空间五种场景图标。

## 06 叫应页｜“收到”为什么还不够

- **页面目的**：讲清基层叫应机制。
- **标题**：发送 → 接收 → 复述 → 行动 → 回报
- **正文**：县级传到乡镇，乡镇叫应村和包片干部，村级逐户联系重点家庭；上级继续核对谁已转、谁失联、哪里需要支援。
- **重点句**：**叫应的验收标准不是聊天框里的“收到”，而是人员已经行动。**
- **视觉方向**：县、乡、村、家庭四级通信网络，每一级都有回执和进度灯。

## 07 转移页｜先接住最难自己离开的人

- **页面目的**：突出特殊群体优先。
- **标题**：老弱病残孕幼，要逐户核对、点对点接送
- **正文**：转移不是广播一响各自离开，要明确包片人员、车辆、主备路线，并把医疗和照护接到安置点。
- **案例角标**：横州组织7458名党员干部和专业力量分片包村。
- **重点句**：**“应转尽转”之前，先回答行动不便者由谁来转。**
- **视觉方向**：重点家庭图标由车辆路线连接医疗安置点，无人物、无人物剪影。

## 08 前置页｜雨来之前，把最难的准备先做完

- **页面目的**：解释力量前置的具体内容。
- **标题**：人先转、点先开、物先备、队先到
- **正文**：提前启用安置点，配置床位、食品、药品和医护；在高风险区域预置通信、发电、储水和救援装备。
- **案例角标**：北京山区村已建成1052个“高地堡垒”。
- **重点句**：**临灾时才找车、找床位、找发电机，往往已经晚了。**
- **视觉方向**：高地安置设施剖面，展示卫星电话、发电机、储水箱、医务室和物资区。

## 09 协同页｜让一条预警触发一组动作

- **页面目的**：说明跨部门联动。
- **标题**：会商、响应、停工停航、撤离、救援同步启动
- **正文**：气象、水利、自然资源、应急、交通、海事和属地共享风险判断，按职责同步行动，并接收基层险情回报。
- **重点句**：**协同不是多个部门各发一条信息，而是同一个风险信号启动共同处置。**
- **视觉方向**：多部门控制节点汇入统一指挥台，再分流到港口、道路、村庄和救援仓库。

## 10 复盘页｜灾后要查行动链哪里断过

- **页面目的**：把救灾推进到能力改进。
- **标题**：别只统计损失，还要追问七个断点
- **正文**：风险是否漏人、预警是否易懂、叫应是否真实、路线是否可走、安置是否够用、通信是否有备份、部门信息是否互通。
- **重点句**：**演练不是证明预案完整，而是提前暴露预案哪里会失灵。**
- **视觉方向**：行动链诊断面板，断点被逐一定位并回写到风险地图和预案。

## 11 收束页｜申论面试直接使用

- **页面目的**：沉淀可迁移表达。
- **标题**：防灾救灾高分公式
- **正文**：排查有底数 → 信息有指向 → 叫应有反馈 → 转移有组织 → 救援有准备 → 事后有复盘
- **重点句**：**把风险想在前、责任落到人、力量放到一线、特殊群体先接住。**
- **视觉方向**：完整防灾闭环覆盖城市、乡村、山区和水系，所有节点转为安全绿色。

## 小红书发布文案

写防灾救灾，别再把“加强监测预警”当成一句完整对策。

预警发到手机，只解决了信息送达。群众是否看懂、村干部是否确认、特殊群体由谁转移、车辆和安置点是否启动、通信中断后有没有备用方案，才决定预警能不能真正减少损失。

人民日报这组材料给出了一条完整行动链：

**风险排查 → 影响预警 → 叫应确认 → 转移安置 → 力量前置 → 协同处置 → 复盘改进**

预警不是通知完成，而是任务开始。发得早，只是争取到时间；有人接、马上动，才能把时间变成安全。
