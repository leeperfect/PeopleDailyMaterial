# 人民日报成稿流程

本流程用于保持人民日报素材库的写作质量稳定。目标不是摘金句或概述文章，而是把真实的人民日报来源转成可复用的教研和发布资产。

## 不可违反的底线

- 用户提供的选题卡是权威 brief：标题、优先级、平台、角度、结构和来源清单是基线，不得偏离。
- 必须先读真实来源。优先读 `data/vault/` 下的 Markdown 文件；如缺失，查 `data/core/articles.jsonl`、`data/raw/` 或 `data/exports/`，并说明来源边界。
- 写稿任务中不得编辑 `data/raw/` 或 `data/core/`。如果某篇稳定官方文章只存在于 core/raw/export 且建立 vault 阅读视图有助于后续复用，可创建一个带元数据和教研速读的 vault Markdown 文件。
- 对每篇已有或新建了 vault Markdown 文件的来源文章，补充带署名和日期的 `Codex 教研速读｜YYYY-MM-DD` callout。
- 按递进逻辑链写作，不是论点加例子的堆叠。每一节必须深化上一节。
- 同时服务教学和发布：解释政策、转译为申论/面试用法，并按需打包公众号/小红书/PPT。
- 格式一致：数字编号标题前缀、Markdown 标题层级、`>` 用于关键引用/题目/公式、加粗关键句、无序列表用于并列要点。
- 参考文章只列作者、文章名称、出版日期、版面，不包含原始链接。
- 参考文章后必须追加 `## 金句集合`，使用一个带编号的 `text` 代码块。

## 必须执行的流程

### 1. 读取规范和来源

- 读 `docs/codex-material-production-plan.md`。
- 跨平台任务同时读 `docs/cross-platform-content-package-workflow.md`。
- 读全部用户提供的来源文章，不只看标题。
- 形成新选题前，同时参考 `data/data_analysis/overview.md`、最新运营报告和既有选题库。

### 2. 标注来源

- 在 YAML/frontmatter 和已有自动批注之后、文章标题之前，插入教研速读 callout。
- 保留原文和已有批注，不删不改。
- 使用 `references/templates.md` 中的稳定字段。

### 3. 先建逻辑再动笔

- 找出读者的常见错误写法。
- 找到主线：因果链、递进链或时间/流程链。
- 把文章浓缩成一个可迁移的公式，如 `规则统一 -> 设施互联 -> 要素流动`。
- 确定每篇来源的贡献类型：政策总纲、具体案例、机制提炼、对比/提醒、考场迁移。

### 4. 生成过程产物

- 选题复盘：`data/analysis/YYYY-MM-DD/YYYY-MM-DD-<slug>-topic-review.md`
- 过程稿：`data/analysis/YYYY-MM-DD/wechat-<slug>.md`
- 平台含小红书时：`data/analysis/YYYY-MM-DD/xiaohongshu-<slug>-card-script.md`
- 平台含 PPT 时：`data/analysis/YYYY-MM-DD/ppt-<slug>-outline.md`
- 平台含面试题卡时：`data/analysis/YYYY-MM-DD/interview-<slug>-card.md`
- 平台含课堂讲稿时：`data/analysis/YYYY-MM-DD/lecture-<slug>.md`

### 5. 写成稿

- 根据来源类型保存到对应系列目录：
  - 人民日报系列：`data/articles/人民日报系列/NN-《人民日报》深度分析【<主题>】：<冲突或收益>.md`（不再使用“人民日报讲<主题>”命名）
  - 热点系列：`data/articles/热点系列/热点N-官媒视角看<热点>：<冲突或收益>.md`
- 编号从 `data/articles/文章索引.md` 末尾确认。当前人民日报系列下一篇使用 44，热点系列下一篇使用热点4。
- 热点系列开头重点回答"官媒为什么这样分析、不同媒体分别抓住了什么"，不预设"很多同学第一反应是什么"。
- 成稿结构使用 `references/templates.md` 中的骨架。

### 6. 同步索引并验收

- 更新 `data/articles/文章索引.md`。
- 按 `references/output-checklist.md` 验收：callout、参考文章、正文无原始链接、金句集合、索引条目。
- 用户未明确要求时不自动提交 Git。

### 7. 同步到 Notion 自媒体内容分发台账

成稿落盘并更新索引后，运行：

```bash
python3 scripts/sync_articles_to_notion_distribution.py --dry-run
```

确认预览无误后执行同步：

```bash
python3 scripts/sync_articles_to_notion_distribution.py --delay 0.25
```

这一步会：
- 扫描 `data/articles/` 下的成稿，对比 Notion 已有记录。
- 为新文章在内容库中创建一条内容记录（标题、主题、日期、本地路径、字数）。
- 为新文章按 8 个发布目标（公众号文章/图文、视频号、小红书图文/视频、抖音、快手、微博）各创建一条分发记录，状态为"待发布"。
- 已存在的记录不重复创建，不覆盖发布状态、发布时间和发布链接。

注意：这一步只同步文章元信息，不同步正文。二润和公众号草稿同步不会影响 Notion 分发台账的已有记录。

## 文章逻辑模式

默认结构：

- **事件开头**：面向普通读者，从一个具体事件、场景或悬念切入，吸引读者往下看；不预设读者是公考考生，不用“很多同学”“写申论这类题”式开头，不先铺宏观背景。保留完整逻辑链：事件引出真问题，真问题接核心判断。
- **核心判断**：一个引用块公式，点明真正要讲清的机制。
- **第一节**：用来源事实和考场转译解释第一层。
- **第二节**：深化逻辑，不只是加第二个例子。
- **第三节**：完成链条，展示读者可以迁移什么。
- **国考省考申论面试迁移**：单独成节，标题统一为“国考省考申论面试怎么用”，给出申论公式和至少一道面试题/答题框架。
- **结尾**：完成认知升级，不喊口号。
- **参考文章和金句集合**：按固定格式收尾。

好的递进方向：

- `误区 -> 真实问题 -> 治理机制 -> 考场表达`
- `政策总纲 -> 具体场景 -> 方法提炼 -> 答题迁移`
- `发现问题 -> 责任承接 -> 协同解决 -> 反馈长效`

坏的递进方向：

- `观点1 + 案例1；观点2 + 案例2；观点3 + 案例3`，节与节之间没有递进关系。
- 大段政策背景写在读者痛点前面。
- 只有事实，没有"申论怎么用、面试怎么答、不能怎么误用"。

## 跨平台默认规则

- 用户说"公众号 + 小红书"时：写成稿和小红书卡片脚本，不生成图片，除非用户明确要求出图/出卡片。
- 小红书图片/卡片：默认 AI 生成无人物视觉，最多 18 张卡片，仅在内容需要时使用。
- 图片工作：中文文字由 Markdown/HTML/PPTX 控制排版，图像生成只用于无文字背景、纹理和视觉素材。
- 用户说"公众号 + PPT"时：写大纲（幻灯片标题、屏幕内容和讲解提示），仅在用户明确要求时创建 PPTX 文件。

## 排版和 Markdown 规则

- 标题和小标题用 `#`、`##`、`###`，方便快速扫读结构。
- 关键概念第一次出现时加粗，如 `**城市体检**`、`**服务前移**`。
- 重要结论用引用块单独展示。
- 面试题题干用引用块，答题步骤用加粗编号段落。
- 申论可用表达用引用块。
- 不整段加粗，不为追求口播感把整篇写成一行一句。
- 连续解释的短句合并成 2-4 句自然段，转折句和结论句可单独成段。

## 验收清单

最终回复前必须运行 `references/output-checklist.md` 中的检查项。
